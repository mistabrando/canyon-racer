## 3. Mobile `@media (max-width:430px)` verdict — yes, it is backwards

`src/style.css:56-64` shrinks **five** text elements on phones and narrows `#best`:

- `#time` 30→24px (−20%), `#day` 13→11px, `#speed` 12→11px, `#best` 12→11px, `.modebtn` 12→11px.

Assessment (opinion, grounded in the facts above): shrinking is the wrong direction.
Phones are held at roughly the same distance as a laptop, with smaller physical pixels,
more glare, more shake, and a touch (not mouse) pointer — everything argues for equal
or larger type, not smaller. The likely motive (fitting the 3-item topbar into 320–360px)
is real, but the fix should be layout (ellipsis on `#best`, nowrap on `#day`, smaller
`gap` — the query already reduces `#timewrap` gap 8→6px and moderow gap 8→6px) rather
than cutting font size below the 13px floor.

Concrete replacement for the block (integrator-ready numbers):

```css
@media (max-width: 430px) {
  #moderow { gap:6px; }
  .modebtn { font-size:13px; padding:12px 8px; letter-spacing:.02em; }
  #time { font-size:28px; }
  #timewrap { gap:6px; }
  #day { font-size:13px; letter-spacing:.05em; white-space:nowrap; }
  #speed { font-size:13px; }
  #best { font-size:13px; max-width:32vw; white-space:nowrap; overflow:hidden; text-overflow:ellipsis; }
  #msg { font-size:17px; min-height:44px; }
  #lesson { font-size:14px; min-height:36px; }
}
```

Nothing in this replacement changes desktop layout; the added `min-height` lines reserve
the wrap space that today causes mid-run shift.

## 5. Layout risks at small widths (facts + opinion marked)

- **Topbar overflow (fact + opinion).** `#topbar` is `space-between` with three children and
  no `min-width:0`/ellipsis anywhere. `#best` caps at 34vw/30vw but without
  `overflow:hidden` the cap does nothing for a single long word; `FRIEND 1:23.45` wraps
  instead. At 320px: `#day` (~150px at 13px ls .08em) + `#timewrap` (time ~110px at 24px +
  speed ~60px) + `#best` (96px cap) ≈ 416px > 320 − 28px padding → overflow. The 430px
  query "fixes" this by shrinking type — the backwards trade criticised in §3. Recommended:
  ellipsis + nowrap (§A1, §A4) instead of smaller type.
- **`#msg` 2-line wrap shift (fact).** No `min-height` on `#msg`; stuck/off-course strings are
  35–39 chars. First wrap pushes `#exitfb/#lesson/#penalty/#split` down ~18px mid-crisis.
  Reserve it (§A6).
- **`#lesson` 2-line push (fact).** `min-height:16px` reserves one 12px line; the practice
  string needs two. Same fix (§A8).
- **`#presult` button shift on finish (fact).** `min-height:22px` = one line; finish strings
  (§C6) need two. Reserve 44px.
- **`#panelcard` on short landscape phones (fact).** `max-height:calc(100dvh − 32px)` +
  `overflow-y:auto` + `touch-action:pan-y` already handle it — no finding, noted so the
  integrator does not "fix" what works. `#panel` has `padding:16px` without safe-area;
  content stays clear because the card is centred — no change needed (opinion).

## 6. Mobile vs desktop notes

- Desktop (keyboard): viewing distance larger, pointer precise. Current 12px HUD values are
  marginal but the static mock understates the problem — see §7 driving context.
- Mobile (touch): smaller physical text, glare, shake, fat-finger targets. The media query
  currently makes all of this worse (§3). Touch-only elements (`#driftbtn` explicit size
  missing, `#resetbtn` 11px/40px) need the largest fixes, not the smallest type.
- Panel: same card both platforms (`width:min(420px,92vw)`). 320px-wide phones fit today
  only because `.modebtn` shrinks to 11px — prefer `flex-wrap` fallback over 11px (§C4).

## 7. Driving-context note (opinion, as requested — separated from facts)

Static-mock "acceptable" (≈12px dimmed small caps on a still) is not in-play acceptable.
At ~140 u/s the background is translating fast, dust/skid particles cross the text, and
the driver's fovea is on the road, not the HUD — text is read in 100–300ms peripheral
glances. That is why the ranked list weights transient, motion-time text (`#msg` rescue
lines, `#penalty`, `#exitfb`, `#delta`) above static panel text even when the panel text
is technically smaller (`#ctrlrow` 11px loses to `#penalty` 13px in severity because the
penalty is read at speed with a 1–2s lifetime).

## 8. CJK / wide-glyph / safe-area interactions (facts + one opinion)

- **CJK (fact):** `html lang="en"`, system font stack (`-apple-system, system-ui, "SF Pro"`),
  no CJK font declared — CJK falls back to system defaults, fine. Two risks if localised:
  (a) `letter-spacing:.08em` on `#day`/`#pdate` and `.06em` on `#exitfb`/`#resetbtn` opens
  CJK glyphs unnaturally — reset `letter-spacing:0` under `:lang(zh), :lang(ja), :lang(ko)`;

  Wide-glyph overflow: `#best` ellipsis fix (§A4) and `#moderow` wrap fallback (§C4) cover
  wider glyphs without new work.
- **`env(safe-area-inset-*)` (fact):** honoured in `#topbar` (top), `#progress` (top),

- **`maximum-scale=1, user-scalable=no`** (`index.html:5`) blocks pinch-zoom as an
  accessibility fallback — the audit's premise (type must be big enough without zoom)
  therefore holds; flagging so the integrator does not rely on "users can zoom".
